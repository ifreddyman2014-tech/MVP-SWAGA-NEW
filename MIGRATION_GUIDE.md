# Руководство по миграции клиентов между серверами

## Описание

Скрипт `migrate_clients.py` позволяет переносить активных VPN клиентов с одного или нескольких серверов на целевой сервер. Это полезно в случаях:

- Сервер перестал работать или работает нестабильно
- Необходимо консолидировать пользователей на более мощном сервере
- Смена хостинг-провайдера
- Балансировка нагрузки

## Возможности

✅ **Миграция с сохранением UUID** - клиенты сохраняют свой UUID, что обеспечивает бесшовную миграцию
✅ **Пакетная миграция** - можно мигрировать сразу с нескольких серверов
✅ **Dry-run режим** - проверка без фактических изменений
✅ **Автоматическое обновление БД** - записи в базе данных обновляются автоматически
✅ **Удаление с исходного сервера** - опция очистки клиентов после миграции
✅ **Подробный отчет** - JSON отчет с результатами миграции

## Требования

Перед миграцией убедитесь что:

1. ✅ Целевой сервер настроен и работает
2. ✅ В `servers.json` добавлена конфигурация целевого сервера
3. ✅ На целевом сервере создан VLESS inbound с Reality
4. ✅ База данных содержит записи о серверах
5. ✅ У вас есть доступ к 3X-UI панелям всех серверов

## Использование

### 1. Проверка миграции (Dry Run)

**ВСЕГДА** начинайте с dry-run режима для проверки:

```bash
python migrate_clients.py --from de1 --to fi1 --dry-run
```

Это покажет:
- Сколько клиентов будет мигрировано
- Информацию о каждом клиенте
- Возможные ошибки

### 2. Миграция с одного сервера

```bash
# Мигрировать клиентов с Germany на Finland
python migrate_clients.py --from de1 --to fi1
```

### 3. Миграция с нескольких серверов

```bash
# Мигрировать клиентов с Germany и Latvia на Finland
python migrate_clients.py --from de1,lv1 --to fi1
```

### 4. Миграция с удалением исходных клиентов

```bash
# Мигрировать и удалить клиентов с исходного сервера
python migrate_clients.py --from de1 --to fi1 --delete-source
```

⚠️ **ВНИМАНИЕ**: Используйте `--delete-source` только после того, как убедитесь что миграция прошла успешно!

## Параметры командной строки

| Параметр | Описание | Пример |
|----------|----------|--------|
| `--from` | ID исходного(ых) сервера(ов), через запятую | `--from de1,lv1` |
| `--to` | ID целевого сервера | `--to fi1` |
| `--delete-source` | Удалить клиентов с исходного сервера после миграции | `--delete-source` |
| `--dry-run` | Режим проверки без фактических изменений | `--dry-run` |

## ID серверов

| ID | Название | Описание |

## Примеры миграции

### Пример 1: Простая миграция

```bash
# 1. Проверка
python migrate_clients.py --from de1 --to fi1 --dry-run

# 2. Миграция
python migrate_clients.py --from de1 --to fi1

# 3. Проверка отчета
cat migration_report_*.json | jq '.success_rate'
```

### Пример 2: Консолидация на один сервер

```bash
# Мигрировать всех пользователей на Finland
python migrate_clients.py --from de1,lv1 --to fi1

# Проверить что все успешно мигрировали
cat migration_report_*.json | jq '.failed'

# Если failed = 0, удалить клиентов с исходных серверов
python migrate_clients.py --from de1,lv1 --to fi1 --delete-source --dry-run
python migrate_clients.py --from de1,lv1 --to fi1 --delete-source
```

### Пример 3: Миграция с уведомлением пользователей

```bash
# 1. Мигрировать клиентов
python migrate_clients.py --from de1 --to fi1

# 2. Получить список telegram_id пользователей для уведомления
cat migration_report_*.json | jq -r '.migrated_users[].telegram_id'

# 3. Отправить массовое уведомление (см. раздел ниже)
python notify_users.py --report migration_report_*.json
```

## Решение проблем

### Ошибка: "Source server not found in database"

```bash
# Проверьте что сервер существует в БД
python -c "from src.database.models import Server; from src.database.session import get_session; import asyncio; async def check(): async for s in get_session(): print([srv.id for srv in (await s.execute(select(Server))).scalars().all()]); asyncio.run(check())"
```

### Ошибка: "Failed to authenticate with 3X-UI panel"

Проверьте параметры в `servers.json`:
- `xui_host` - правильный IP/домен
- `xui_port` - правильный порт панели
- `xui_username` / `xui_password` - правильные учетные данные

```bash
# Проверить доступность панели
curl -k https://144.31.132.116:334/b07En1ZZsNtdTXo426/login
```

### Ошибка: "Client not found on source server"

Клиент был удален или не синхронизирован. Варианты:
1. Пропустить этого клиента (он уже удален)
2. Создать клиента заново на целевом сервере

### Низкий success_rate

Если успешность миграции < 90%:
1. Проверьте логи: `migration.log`
2. Проверьте доступность исходного и целевого серверов
3. Убедитесь что на целевом сервере есть место (max_users)

## Логи

Все операции логируются в два места:
- **Консоль** - для мониторинга в реальном времени
- **migration.log** - для детального анализа

```bash
# Просмотр логов
tail -f migration.log

# Поиск ошибок
grep "ERROR" migration.log
grep "Failed" migration.log
```

## Безопасность

⚠️ **Важные меры безопасности:**

1. **Всегда используйте dry-run перед миграцией**
2. **Создайте backup базы данных перед миграцией**
   ```bash
   cp vpn_bot.db vpn_bot.db.backup_$(date +%Y%m%d)
   ```
3. **Не удаляйте клиентов с исходного сервера (`--delete-source`) пока не убедитесь что миграция успешна**
4. **Сохраняйте отчеты о миграции** для аудита

## FAQ

**Q: Нужно ли пользователям обновлять конфигурацию?**
A: Да, пользователям нужно получить новую конфигурацию, так как изменился сервер (IP, порт, ключи Reality).

**Q: Сохраняется ли срок действия подписки?**
A: Да, срок действия (expiryTime) копируется с исходного сервера.

**Q: Что если миграция прервется?**
A: Скрипт идемпотентен - можно запустить повторно. Уже мигрированные клиенты будут пропущены.

**Q: Можно ли мигрировать только определенных пользователей?**
A: В текущей версии - нет. Мигрируются все активные клиенты с сервера. Для выборочной миграции нужно модифицировать скрипт.

**Q: Как откатить миграцию?**
A: Запустите миграцию в обратном направлении (--from fi1 --to de1), используя бэкап БД.
